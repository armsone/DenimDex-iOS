# DenimDex 기술서 v2.0 — AIBI Edition

문서 상태: 구현 기준 초안 — 자료 0건 출발 기준  
대상: DenimDex iPhone 앱  
핵심 엔진: AIBI(AI Browser Interface)  
작성일: 2026-08-28

## 1. 제품 정의

DenimDex는 빈티지 데님 사진을 빠르게 분석하여 제품 후보, 상태, 참고 가치 범위를 먼저 보여주고 필요할 때만 정밀 조사를 이어 가는 개인용 가치 판단 앱이다.

한 문장으로 정의하면 다음과 같다.

> 찍으면 먼저 가격 범위를 보여주고, 더 알고 싶을 때 감정사처럼 근거를 좁혀 가는 빈티지 데님 도감.

DenimDex가 사용자에게 제공해야 할 결과는 단순한 제품명 하나가 아니다.

- 어떤 제품일 가능성이 높은가
- 사진에서 실제로 확인된 특징은 무엇인가
- 아직 확인하지 못한 특징은 무엇인가
- 다음에 어떤 부분을 촬영해야 하는가
- 내 도감에 어떤 기록으로 남길 것인가
- 현재 상태와 비교 사례를 기준으로 어느 정도의 참고 가치가 있는가
- 이 판단을 얼마나 신뢰할 수 있는가

DenimDex는 정품 인증서나 공식 감정서가 아니다. AI의 추정과 사용자가 확인할 수 있는 근거를 제공하는 조사 도구다.

## 2. v1.0에서 v2.0으로 바뀌는 핵심

| v1.0 역할 | v2.0 해석 |
|---|---|
| 앱이 사진을 서버로 전송 | 앱이 사진 사본을 AIBI 작업에 직접 첨부 |
| DenimDex 서버가 OpenAI API 호출 | AIBI가 사용자의 로그인된 공식 AI 웹 세션 사용 |
| API Key를 서버에서 보관 | 개발자 API Key 자체를 사용하지 않음 |
| 중앙 Archive DB 검색 | 처음에는 AI 일반 지식과 사진으로 판단하고, 결과를 개인 도감에 축적. NAS에는 최소 공동 자료만 수집 |
| 서버가 AI 결과를 구조화 | 앱이 구조화 출력 계약을 검증한 뒤 로컬 저장 |
| 서버가 분석 세션 관리 | 기기 내 로컬 분석 세션이 사진·관찰·후속 질문 관리 |
| 클라우드 이미지 저장소 | 원본은 사진 보관함 또는 앱 로컬 저장소, 전송용 사본은 작업 후 폐기 |
| 웹 관리자에서 즉시 데이터 수정 | 초기에는 제거. 검증 자료가 생긴 뒤에만 별도 Archive 제작 도구 도입 |
| 서버 장애 처리 | AI 로그인, 웹 UI 변경, 네트워크, 자동 첨부 실패를 구분하여 처리 |

현재 확보된 것은 기술서와 AIBI뿐이며 제품 데이터, 가격 데이터, 이미지, 기존 소스는 0건으로 가정한다. 존재하지 않는 Archive를 전제로 기능을 만들지 않는다. 이 변화로 정기적인 클라우드 앱 서버, 대형 데이터베이스, 이미지 저장소, API Key 관리가 필요 없어진다. 대신 AI 제공자의 웹 화면 변경 대응, NAS 최소 서비스 보안, 백업, 향후 검증 데이터 제작은 계속 필요하다. 따라서 목표는 **추가 월 클라우드 서버비 최소화**이지 **모든 관리 작업 0**을 보장하는 것이 아니다.

## 3. 설계 원칙

1. 빠른 가치 판단 경로에 서버 의존성을 두지 않는다.
2. 개발자 소유 AI API Key를 앱에 넣지 않는다.
3. 사용자는 자신이 선택한 AI 제공자의 공식 웹사이트에 직접 로그인한다.
4. 로그인 비밀번호, 쿠키, 토큰을 앱이 읽거나 보관하지 않는다.
5. 분석 세션과 사용자의 개인 도감은 기기 안에서 동작한다.
6. AI의 답변을 사실로 바로 표시하지 않고 앱의 결과 계약을 통과시킨다.
7. 기본 경로에서는 제품 후보와 참고 가치를 한 번의 AI 요청으로 받아 속도를 우선한다.
8. 정밀 식별과 근거 조사는 사용자가 선택할 때만 별도 요청으로 실행한다.
9. 가치에는 가격 하나가 아니라 범위, 기준일, 통화, 근거 수준, 불확실성을 표시한다.
10. AI가 확신하지 못하면 추측을 강화하지 않고 다음 증거 사진을 한 장만 요청한다.
11. AIBI 엔진과 DenimDex 제품 규칙을 분리하여 다른 앱에서도 엔진을 재사용할 수 있게 한다.

## 4. 전체 구조

```text
사용자
  ↓ 촬영·사진 선택
DenimDex iPhone 앱
  ├─ Camera & Evidence Photos
  ├─ Local Analysis Session
  ├─ Local Personal Collection
  ├─ Prompt Builder
  ├─ Result Validator
  └─ AIBI Host Adapter
          ↓
      Portable AIBI Engine
          ↓
  공식 AI 웹사이트
  ChatGPT / Gemini / Claude
          ↓
  구조화된 분석 텍스트
          ↓
  Result Validator → 빠른 가치 카드 및 개인 도감 저장
```

가치 판단의 핵심 경로에는 백엔드, 자체 계정 서버, 원격 이미지 저장소가 존재하지 않는다. 선택적인 NAS 공동 도감 서비스는 분석 결과가 표시된 뒤 최소 구조화 자료를 수집하고 검증된 Archive를 배포하는 역할만 한다.

## 5. 기술 선택

### 5.1 iPhone 앱

- Swift 5.9 이상
- SwiftUI
- 최소 iOS 17 권장
- 카메라: AVFoundation
- 사진 선택: PhotosUI
- AI 웹 통합: WebKit의 `WKWebView`
- 로컬 영속성: SwiftData 또는 SQLite
- 개인 도감 검색: SwiftData, 데이터가 커지면 SQLite FTS5
- 민감하지 않은 설정: `UserDefaults`

기존 React Native 프로토타입은 제품 동작 참고 자료로 사용한다. AIBI는 WebKit의 생명주기, 화면 부착, 파일 선택, 세션 공유를 정밀하게 제어해야 하므로 iPhone 정식 버전은 네이티브 SwiftUI를 우선한다.

### 5.2 Android

Android는 별도 네이티브 앱으로 만들 수 있다. 제품 계약과 Archive 스키마는 공유하되 플랫폼 엔진은 Android WebView에 맞게 구현한다. iPhone MVP가 확정되기 전에는 동시 구현하지 않는다.

## 6. AIBI의 역할과 경계

AIBI는 사용자가 로그인한 AI 제공자의 웹 세션을 재사용하여 다음 작업만 담당한다.

- 로그인 상태 확인
- 최대 8장의 순서 있는 증거 사진 사본 첨부
- DenimDex가 만든 프롬프트 입력
- 실제 전송 성공 확인
- 스트리밍 답변 관찰
- 동일 결과가 연속 관찰된 뒤 완료 판정
- 정리된 텍스트를 DenimDex 결과 수신부에 한 번만 전달
- 자동 진행이 불가능할 때 사용자가 볼 수 있는 브라우저로 안전하게 전환

AIBI는 다음을 담당하지 않는다.

- 제품 판별 규칙
- Archive 검색과 데이터 보관
- 가격의 정확성 보증
- 정품 인증
- 거래 중개
- 사용자 비밀번호 또는 쿠키 수집
- CAPTCHA나 보안 확인 우회

### 6.1 지원 제공자

초기 MVP는 한 제공자부터 시작한다. 제품 품질과 유지보수 범위를 고려하면 ChatGPT를 1차 제공자로 구현하고, 같은 결과 계약이 안정화된 뒤 Gemini와 Claude를 추가한다.

제공자 버튼은 한 번 누르면 바로 분석을 시작한다. 별도 제공자 선택 후 실행 버튼을 두지 않는다.

### 6.2 AIBI 필수 동작

- 로그인·실행 브라우저는 `WKWebsiteDataStore.default()`를 공유한다.
- 로그인 상태는 쿠키 유무가 아니라 화면에 보이는 작성기와 계정 표식으로 판정한다.
- 숨김 브라우저도 실제 화면 계층에 375×667 크기로 붙여 둔다.
- 기본 실행 방식은 `필요할 때만 AI 브라우저 표시`다.
- 로그인, 보안 확인, 입력창 탐색 실패, 사진 첨부 실패 시 새 보이는 브라우저로 전환한다.
- 네트워크 오류나 제공자 오류는 브라우저를 강제로 열지 않고 앱에서 설명한다.
- 빠른 판단은 전송 확인 후 45초에 종료한다. 정밀 조사는 사용자가 선택한 경우에만 최대 1분 59초를 허용한다.
- 진행 중에는 남은 시간, 줄어드는 진행 바, 취소 버튼을 항상 표시한다.
- 결과는 비어 있지 않고 생성이 끝났으며 3회 같은 내용으로 관찰되어야 완료된다.
- 다른 작업의 늦은 콜백이 현재 세션을 덮어쓰지 않도록 작업 ID를 사용한다.

## 7. 사진 증거 시스템

사진은 단순 첨부가 아니라 의미가 있는 증거로 관리한다.

### 7.1 사진 역할

```text
overall_front       전체 앞면
overall_back        전체 뒷면
red_tab             레드탭 또는 브랜드 탭
top_button_front    상단 버튼 앞면
top_button_back     상단 버튼 뒷면 각인
care_label          케어라벨
patch               가죽·종이 패치
rivets              리벳과 숨은 리벳
zipper_or_fly       지퍼 또는 버튼 플라이
selvedge            셀비지
stitching           봉제와 아큐에이트
damage              오염·수선·마모
scale_reference     크기 비교 기준
```

빠른 판단은 전체 앞면과 라벨·패치 등 식별력이 높은 사진 2장으로 시작하며 최대 3장만 보낸다. 사진이 많을수록 업로드와 AI 처리 시간이 늘기 때문이다. 정밀 조사에만 최대 8장을 허용한다.

### 7.2 전송 사본 정책

- 원본을 수정하지 않는다.
- 긴 변 최대 2,048px의 JPEG 사본을 순차 생성한다.
- 시작 품질은 0.84, 사진당 최대 2MB다.
- EXIF, GPS, 원본 파일명 등 개인정보성 메타데이터를 제거한다.
- `aibi-01.jpg` 같은 새 파일명으로 순서를 보존한다.
- 모든 사진의 AI 웹 미리보기가 확인되기 전에는 프롬프트를 보내지 않는다.
- 일부 사진만 첨부된 상태로 분석을 시작하지 않는다.
- 작업이 끝나거나 취소되면 임시 전송 파일을 폐기한다.

## 8. 분석 세션

`AnalysisSession`은 하나의 데님을 조사하는 로컬 작업 단위다.

```text
AnalysisSession
  id
  createdAt / updatedAt
  title
  status
  evidencePhotos[]
  observations[]
  candidateProducts[]
  missingEvidence[]
  conversations[]
  identificationConclusion?
  valuationConclusion?
  linkedArchiveProductId?
```

AI 웹 대화방 자체를 유일한 세션 저장소로 사용하지 않는다. 매 요청마다 앱이 지금까지 확정된 관찰과 후보를 짧은 세션 요약으로 만들어 보낸다. 이렇게 해야 제공자를 바꾸거나 새 대화를 시작해도 분석을 계속할 수 있다.

세션의 정보는 세 종류로 구분한다.

- `observed`: 사진에서 직접 확인된 사실
- `reported`: 사용자가 입력한 사실
- `inferred`: AI가 추론한 내용

AI의 추론이 다음 요청에서 관찰 사실처럼 재사용되지 않도록 출처를 유지한다.

## 9. 속도 우선 AI 분석

DenimDex는 첫 결과가 빠르지 않으면 제품 가치가 없다고 본다. 기본 경로는 여러 번 질문하는 감정 절차가 아니라 한 번의 AIBI 요청으로 끝나는 `Quick Value`다.

### 9.1 Quick Value — 기본 경로

```text
사진 2장 촬영 또는 선택
  ↓
앱이 전송용 사본을 만드는 동안 AIBI 화면 미리 준비
  ↓
사진 + 짧은 고정 프롬프트를 한 번에 전송
  ↓
제품 후보 + 상태 + 참고 가격 범위 + 신뢰도 동시 반환
  ↓
즉시 가치 카드 표시
```

Quick Value의 규칙:

- AI 요청은 1회다.
- 기본 사진은 전체 모습 1장과 라벨·패치·탭 중 가장 선명한 사진 1장이다.
- 사용자가 브랜드나 통화를 입력하지 않아도 시작할 수 있다.
- 결과 설명은 짧게 제한하여 생성 시간을 줄인다.
- AI가 부족하다고 판단하면 가장 정보 가치가 높은 추가 사진 한 장만 요청한다.
- 전송 확인 뒤 45초가 지나면 빠른 판단을 종료하고 재시도 또는 정밀 조사를 제안한다.
- 확인 가능한 시세 출처가 없어도 일반 지식 기반의 넓은 참고 범위는 표시할 수 있지만 반드시 `빠른 AI 추정`으로 표시한다.

### 9.2 Deep Inspect — 선택 경로

사용자가 `더 정확히 알아보기`를 눌렀을 때만 실행한다.

- 최대 8장의 증거 사진
- 제품의 세부 연대와 모델 후보
- 후보별 일치·충돌 근거
- 버튼 각인, 탭, 패치, 리벳, 봉제 특징 확인
- 판매 완료 가격과 판매 희망 가격 구분
- 비교 사례의 제목, 가격, 상태, 날짜, 출처 URL 요청
- 최대 1분 59초 대기

Deep Inspect가 끝나기 전에도 Quick Value 카드는 사라지지 않는다. 사용자는 첫 결과를 본 상태에서 기다린다.

### 9.3 속도 예산

| 구간 | 목표 | 상한 또는 처리 |
|---|---:|---|
| 카메라 촬영 후 미리보기 | 300ms 이내 | 즉시 로컬 이미지 표시 |
| 사진 2장 정규화 | 1.5초 이내 | 순차 처리, 화면 차단 금지 |
| 준비된 AI 화면에 첨부·전송 | 3초 이내 | 실패 시 바로 보이는 브라우저 전환 |
| Quick Value AI 응답 | 중앙값 15초 목표 | 45초 강제 종료 |
| 결과 파싱과 화면 반영 | 100ms 이내 | 메인 스레드 최소 작업 |
| 전체 체감 시간 | 대부분 20초 이내 목표 | 제공자·네트워크에 따라 보장 불가 |

AIBI 웹 세션은 분석 화면 진입 시 미리 준비하되 사진이나 프롬프트는 사용자가 분석을 누르기 전 전송하지 않는다. 로그인 여부도 촬영이 끝난 뒤 확인하지 말고 설정 또는 앱 활성화 시 미리 확인한다.

### 9.4 가치 표시의 두 등급

- `빠른 AI 추정`: 속도 우선. 비교 URL이 없을 수 있고 넓은 범위를 표시한다.
- `근거 조사`: 속도보다 확인 가능성을 우선. 날짜와 비교 URL이 있는 결과만 표시한다.

두 값을 같은 정확도의 가격처럼 섞지 않는다. 어떤 경우에도 정품 인증이나 실제 매입가를 보장하지 않는다.

## 10. AI 출력 계약

AIBI는 텍스트를 반환하므로, 프롬프트는 설명 없이 하나의 JSON 코드 블록만 출력하도록 요구한다. 앱은 코드 블록을 제거한 뒤 엄격하게 파싱한다.

### 10.1 빠른 가치 결과

```json
{
  "schemaVersion": 1,
  "task": "quick_value",
  "productGuess": {
    "brand": "Levi's",
    "model": "501 계열",
    "era": "판단 어려움"
  },
  "summary": "Levi's 501 계열로 보이며 사용감이 있는 중고 상태",
  "confidence": "medium",
  "currency": "KRW",
  "valueRange": { "low": 80000, "high": 180000 },
  "valueBasis": "ai_general_estimate",
  "condition": "fair",
  "observations": [
    {
      "feature": "fly_type",
      "value": "button_fly",
      "evidencePhotoRole": "overall_front",
      "certainty": "observed"
    }
  ],
  "valueReasons": ["브랜드와 기본 모델 계열 추정", "눈에 띄는 사용감 반영"],
  "nextPhoto": {
    "photoRole": "top_button_back",
    "instruction": "더 정확한 판단을 원하면 상단 버튼 뒷면 각인을 촬영해주세요."
  },
  "caveats": ["빠른 AI 추정이며 정품 감정이나 실제 매입가가 아님"]
}
```

허용 값:

- `confidence`: `high`, `medium`, `low`, `unknown`
- `condition`: `excellent`, `good`, `fair`, `poor`, `unknown`
- `valueBasis`: `ai_general_estimate`, `asking_prices_only`, `mixed_sold_and_asking`, `verified_sold_comparables`, `insufficient_market_data`

### 10.2 근거 조사 결과

```json
{
  "schemaVersion": 1,
  "task": "deep_value",
  "currency": "KRW",
  "range": { "low": 0, "high": 0 },
  "asOfDate": "2026-08-28",
  "confidence": "low",
  "basis": "insufficient_market_data",
  "comparables": [],
  "conditionAdjustments": [],
  "caveats": ["정품 감정 결과가 아님"],
  "nextAction": "완료 거래 비교 사례를 추가로 확인하세요."
}
```

허용 `basis`:

- `verified_sold_comparables`
- `mixed_sold_and_asking`
- `asking_prices_only`
- `ai_general_estimate`
- `insufficient_market_data`

### 10.3 결과 검증

앱은 다음 결과를 거부하고 브라우저를 유지하거나 수동 가져오기를 제공한다.

- JSON 파싱 실패
- 스키마 버전 불일치
- 요청 작업과 다른 `task`
- 허용 목록 밖의 열거 값
- 음수 가격 또는 `low > high`
- 기준일 또는 통화 누락
- URL 형식이 아닌 비교 사례 출처
- 관찰하지 않은 사진 역할을 근거로 사용
- 빈 결과 또는 이전 작업 결과

## 11. 자료 0건에서 시작하는 도감

MVP에는 검증된 공용 제품 Archive가 없다고 가정한다. 샘플 데이터를 실제 자료처럼 꾸미거나 AI가 만든 설명을 검증 자료로 저장하지 않는다.

도감은 두 단계로 성장한다.

### 11.1 My DenimDex — MVP

사용자가 Quick Value 결과에서 `내 도감에 저장`을 누르면 개인 기록이 생성된다.

```text
CollectionItem
  id
  createdAt / updatedAt
  userTitle
  photos[]
  aiProductGuess
  quickValueResult
  deepInspectResult?
  userNotes
  verificationState
```

`verificationState`는 `ai_estimate`, `user_confirmed`, `source_verified`로 구분한다. AI 결과는 처음부터 `source_verified`가 될 수 없다.

개인 도감은 서버 없이 기기 안에서 검색한다. 브랜드, 모델 추정, 메모, 촬영일, 가치 범위를 색인한다.

### 11.2 Verified Archive — 이후 단계

공용 Archive는 다음 조건을 갖춘 자료가 실제로 모인 뒤에만 시작한다.

- 출처와 확인 날짜
- 사용할 권리가 있는 이미지
- 제품 특징을 뒷받침하는 1차 또는 신뢰 가능한 자료
- 사람이 검토한 제품명과 연대
- 변경 이력

향후 데이터는 앱 코드와 분리된 SQLite 패키지로 관리한다. 초기 자료 수집과 구조화는 AI가 보조할 수 있지만, AI가 만든 내용을 무검증 사실로 배포하지 않는다. 앱 업데이트 없이 배포할 필요가 생기면 서명된 패키지를 정적 GitHub Release에 두는 방식을 검토한다.

### 11.3 자료 확보 책임

제품 개발 과정에서 다음 산출물을 함께 만든다.

- 데님 사진 촬영 가이드
- 특징 용어 사전과 사진 역할 정의
- 가치 판단용 상태 등급 기준
- 프롬프트 회귀 테스트용 개인정보 제거 사진 세트
- 출처 기록 양식
- 향후 Archive 입력·검증 도구

외부 판매 사이트 이미지는 권리 확인 없이 앱에 복제하지 않는다. 공개 정보 조사를 통해 얻은 가격은 출처 URL과 확인 날짜를 남기고, 판매 완료가와 판매 희망가를 구분한다.

### 11.4 Community Archive — 사용자와 함께 좋아지는 구조

사용자가 많아질수록 공용 도감이 좋아지는 선순환을 다음과 같이 만든다.

```text
Quick Value 또는 Deep Inspect
  ↓
사용자가 제품명·라벨·가격 근거를 확인 또는 수정
  ↓
공유에 명시적으로 동의
  ↓
개인정보와 원본 사진을 제거한 Contribution Bundle 생성
  ↓
공동 제보함에 저장
  ↓
자동 형식·중복·출처·이상 가격 검사
  ↓
여러 독립 제보의 특징 합의
  ↓
검수 후보
  ↓
서명된 Verified Archive 배포
```

제보 묶음은 다음 정보만 기본 전송한다.

```text
schemaVersion
anonymousContributorKey
normalizedBrand / model / era
observedFeatures[]
condition
priceEvidence[]
sourceURLs[]
country / currency / observedAt
aiProvider / promptVersion
contentFingerprint
```

- 사용자의 원본 사진, 위치, 이름, AI 대화 원문은 기본 제보에서 제외한다.
- 사진이 꼭 필요한 검수는 별도 동의와 사용 권리 확인을 받는다.
- AI 추정 하나는 사실 하나로 세지 않는다.
- 같은 기기의 반복 제보는 독립 근거로 중복 집계하지 않는다.
- 최소 3명의 독립 관찰이 같은 특징에 합의하고 출처가 확인되어야 공용 후보가 된다.
- 가격은 국가, 통화, 관찰 날짜, 판매 완료·판매 희망 유형을 분리하고 시간이 지나면 신뢰 가중치를 낮춘다.
- 터무니없는 가격, 복제된 문장, 상충되는 연대, 출처 없는 정품 주장은 격리한다.
- 검수 전 자료는 다른 사용자의 확정 정보로 노출하지 않는다.

#### 10장 도달 동기화 제안

개인 도감에 `동기화 대기 카드`가 10장 쌓이면 분석 직후가 아니라 사용자가 개인 도감으로 돌아온 시점에 한 번 제안한다. 사용자에게는 기부나 제보가 아니라 개인 도감과 공동 도감을 서로 최신 상태로 맞추는 기능으로 설명한다.

```text
도감을 동기화할까요?

다른 사용자의 도감으로 내 도감을 확장하고,
내 도감도 다른 사람에게 공유합니다.

[지금 동기화]  [다음에]

동기화되는 정보 보기
```

용어는 다음처럼 일관되게 사용한다.

- 사용자에게 보이는 질문: `도감을 동기화할까요?`
- 양방향 기능 이름: `도감 동기화`
- 기본 행동 버튼: `지금 동기화`
- 업로드 단계: `내 카드 반영 중`
- 다운로드 단계: `최신 도감 받는 중`
- 완료: `도감이 확장되었어요`

완료 화면에는 `새 제품 N개 추가`, `내 카드 M개가 공용 도감과 연결됨`처럼 실제 변화를 숫자로 보여준다.

동기화 대기 카드의 조건:

- AIBI 결과가 정상 스키마로 완료됨
- 사용자가 개인 도감에 직접 저장함
- 사용자가 제품 추정을 확인하거나 수정함
- 같은 사진·특징의 중복 카드가 아님
- 이미 제보한 카드가 아님

`동기화되는 정보 보기`에서는 10장을 목록으로 보여주고 사용자가 카드별로 제외할 수 있게 한다. 중앙으로 올라가는 최소 정보와 폰에만 남는 정보를 명확히 표시한다. 최초 동의가 미래의 모든 카드와 사진에 대한 포괄 동의가 되면 안 된다. 사용자가 원하면 설정에서 `카드 10장마다 자동 동기화`를 별도로 켤 수 있다.

`나중에`를 선택하면 계속 방해하지 않고 동기화 대기 카드가 10장 더 늘었을 때 다시 제안한다. 설정에는 언제든 사용할 수 있는 `지금 도감 동기화` 버튼과 자동 제안 끄기를 제공한다.

#### 업로드와 동기화

사용자가 동기화를 승인하면 하나의 동작으로 다음을 수행한다.

```text
선택한 카드에서 최소 Contribution Bundle 생성
  ↓
NAS에 최대 10건 배치 업로드
  ↓
서버가 접수 영수증과 최신 Archive 버전 반환
  ↓
앱이 새 서명 Archive가 있는지 확인
  ↓
변경 패키지만 다운로드·서명 검증
  ↓
로컬 공용 도감 원자적 교체
  ↓
기존 개인 카드와 새 공용 제품을 로컬에서 연결
```

- 개인 카드 원본은 계속 개인 폰에만 남는다.
- 중앙에는 개인 카드 복사본이 아니라 최소 제보 레코드가 저장된다.
- 다른 사용자의 개인 카드를 내 개인 도감에 자동으로 넣지 않는다.
- 검증된 공용 항목만 별도의 `Community Archive`에 나타난다.
- 새 공용 항목이 내 카드와 일치하면 `공용 도감과 연결됨` 배지만 추가한다.
- 업로드 실패 시 암호화된 로컬 Outbox에 보관하고 다음 네트워크 기회에 재시도한다.
- Archive 다운로드는 업로드 성공 여부와 분리한다. 아직 올릴 카드가 없는 사용자도 검증된 공용 도감을 받을 수 있다.
- NAS 응답을 기다리는 동안 Quick Value 화면이나 카메라를 막지 않는다.

NAS는 같은 제품으로 보이는 제보를 `contentFingerprint`와 정규화된 특징으로 묶는다. 중앙에 카드 10장을 그대로 만드는 대신 `제품 후보 1개 + 독립 관찰 10개` 형태로 보관한다. 합의가 높아질수록 특징의 신뢰 점수가 올라가고, 충돌하는 관찰은 삭제하지 않고 검수 대상으로 남긴다.

초기 공동 제보함은 사용자가 보유한 NAS에 둔다. 공용 도감 배포본은 제보함을 앱이 실시간 조회하는 방식이 아니라 검수 후 생성한 서명된 읽기 전용 패키지로 제공한다.

공동 도감 동기화는 Quick Value 경로에서 분리한다. 앱은 마지막으로 검증된 로컬 패키지로 즉시 판단하고, 제보 업로드와 새 Archive 다운로드는 결과 화면 이후 또는 백그라운드에서 수행한다. 공동 기능 장애가 가치 판단 속도를 늦추면 안 된다.

### 11.5 NAS 최소 서비스

NAS는 다음 네 가지 기능만 제공한다.

```text
POST /v1/contributions
  사용자가 동의한 최소 제보 JSON 접수

GET /v1/archive/manifest
  최신 Archive 버전, 크기, 해시, 서명 반환

GET /v1/archive/releases/{version}
  검수된 압축 Archive 패키지 다운로드

POST /v1/feedback
  결과가 맞음·틀림 및 사용자가 고친 최소 정보 접수
```

NAS에 저장하지 않는 것:

- 사용자의 데님 원본 사진
- AI 웹사이트 쿠키·토큰·비밀번호
- 전체 AI 대화 원문과 프롬프트
- 이름, 이메일, 정확한 위치
- 앱 사용 행동 전체 로그

저장소는 처음에는 SQLite 하나로 충분하다. 제보 1건을 수 KB 수준으로 제한하면 수십만 건도 사진 저장보다 훨씬 작다. 원본 제보, 중복 판정, 검수 상태, Archive 릴리스 메타데이터만 보관한다.

```text
contributions
feedback
source_evidence
candidate_products
review_decisions
archive_releases
```

보안 원칙:

- NAS 관리 화면을 인터넷에 직접 노출하지 않는다.
- 앱 API만 별도 컨테이너와 HTTPS reverse proxy를 통해 공개한다.
- 관리용 포트와 데이터베이스 포트는 외부에서 접근할 수 없게 한다.
- 본문 크기 제한, 요청 속도 제한, 스키마 검증, 중복 해시, 악성 URL 차단을 적용한다.
- Archive 릴리스는 NAS와 분리해 보관한 Ed25519 개인키로 서명하고 앱은 내장 공개키로 검증한다.
- NAS가 해킹되어도 위조 Archive가 앱에 설치되지 않게 한다.
- NAS 장애 시 앱의 촬영, AIBI 가치 판단, 개인 도감은 그대로 동작한다.

NAS는 별도 클라우드 사용료를 줄일 수 있지만 전기, 도메인·인증서 구성, 백업, 보안 업데이트와 장애 대응은 남는다. 따라서 `비용 0`보다는 `기존 NAS를 이용한 추가 월 서버비 최소화`가 정확한 표현이다.

## 12. 개인 도감 검색

MVP 검색 대상은 사용자가 저장한 분석 결과다.

- 브랜드와 모델 추정
- 사용자 제목과 메모
- 촬영 날짜
- 상태 등급
- 가치 범위
- 검증 상태

공용 Archive 검색 UI는 실제 검증 자료가 생기기 전에는 노출하지 않는다.

## 13. 화면 구조

### 13.1 주요 탭

```text
Scan       촬영과 빠른 가치 판단
My Denim  저장한 개인 도감과 검색
Learn      촬영법·상태 기준·용어 안내
Settings  AI 로그인과 실행 설정
```

### 13.2 분석 흐름

```text
빠른 가치 확인
  ↓
전체 모습과 식별 부위, 기본 2장 촬영
  ↓
바로 가치 확인
  ↓
AIBI가 준비된 ChatGPT 화면에 한 번 전송
  ↓
AIBI 진행 행: 단계 + 0:45 카운트다운 + 진행 바 + 취소
  ↓
제품 후보 + 상태 + 빠른 참고 가격 범위
  ├─ 내 도감에 저장
  ├─ 요청된 사진 한 장 추가
  └─ 더 정확히 알아보기
```

### 13.3 결과 화면 원칙

- 가장 먼저 보이는 정보는 참고 가격 범위이며, 바로 옆에 `빠른 AI 추정` 등급을 표시한다.
- `높은 가능성`, `가능성 있음`, `판단 불가`를 색상뿐 아니라 문구와 아이콘으로 구분한다.
- 확인된 사실과 AI 추론을 별도 영역에 표시한다.
- 후보마다 일치 근거와 충돌 근거를 함께 표시한다.
- 추가 사진 요청은 바로 카메라를 여는 행동 버튼이어야 한다.
- 가격은 단일 숫자가 아니라 범위로 표시한다.
- 비교 출처가 없으면 눈에 띄는 경고를 표시한다.

## 14. 설정

설정에는 AIBI 관련 항목을 한곳에 모은다.

- AI 제공자별 상태: `확인 중`, `로그인됨`, `로그인 필요`
- 공식 AI 로그인 화면 열기
- 실행 방식
  - 필요할 때만 AI 브라우저 표시(기본값)
  - 항상 AI 브라우저 표시
- 제공자별 세션 데이터 지우기
- 사진 원본 보관 정책
- 분석 세션 전체 삭제
- 개인정보 및 면책 안내

## 15. 개인정보와 보안

- 비밀번호, 쿠키, 세션 토큰을 앱 코드로 읽지 않는다.
- 자동화 스크립트는 허용된 AI 공식 origin에서만 실행한다.
- OAuth, 결제, 제3자 인증 origin에는 스크립트를 주입하지 않는다.
- 로그에 사진, 프롬프트, AI 답변, 쿠키, 전체 URL을 기록하지 않는다.
- 진단에는 제공자, 단계, 소요 시간, 익명 오류 코드, 결과 길이만 남긴다.
- 사용자 사진은 기본적으로 기기 밖의 DenimDex 서버에 저장되지 않는다.
- 단, 사용자가 선택한 AI 제공자 웹사이트에는 분석을 위해 사진과 프롬프트가 전송됨을 작업 전에 알린다.
- 앱 삭제 또는 사용자 삭제 요청 시 로컬 세션과 앱 소유 사진 사본을 제거한다.

## 16. 오류와 복구

| 상황 | 사용자 메시지 | 행동 |
|---|---|---|
| 인터넷 없음 | 인터넷 연결을 확인해주세요. | 작업 보존, 재시도 |
| AI 로그인 필요 | ChatGPT 로그인이 필요합니다. | 공식 로그인 화면 표시 |
| CAPTCHA·보안 확인 | 화면에서 보안 확인을 완료해주세요. | 보이는 브라우저 전환 |
| 사진 전체 첨부 실패 | 사진을 모두 첨부하지 못했습니다. 화면에서 확인해주세요. | 부분 전송 금지, 보이는 브라우저 전환 |
| AI 입력창 변경 | 자동 입력을 완료하지 못했습니다. | 수동 복사·붙여넣기 제공 |
| AI 제공자 오류 | 현재 AI가 요청을 처리하지 못했습니다. | 브라우저 자동 표시 없이 재시도 안내 |
| 빠른 판단 45초 초과 | 빠른 판단 시간이 초과되었습니다. 다시 시도하거나 정밀 조사를 선택해주세요. | 작업 취소, 사진 보존 |
| 정밀 조사 1분 59초 초과 | 정밀 조사 응답 시간이 초과되었습니다. | 작업 취소, 세션 보존 |
| JSON 검증 실패 | 결과 형식을 확인하지 못했습니다. | 브라우저 유지, 수동 가져오기 |
| 제품 판단 불가 | 현재 사진만으로 제품을 판단하기 어렵습니다. | 가장 필요한 사진 한 장 요청 |
| 시장 자료 부족 | 확인 가능한 거래 자료가 부족합니다. | 금액 확정 표시 금지 |

항상 `프롬프트 복사`, `AI 브라우저 열기`, `결과 붙여넣기`의 수동 복구 경로를 제공한다.

## 19. 완료 기준

MVP는 다음 조건을 모두 충족해야 완료다.

- 서버 주소와 개발자 AI API Key가 앱에 존재하지 않는다.
- 네트워크가 없어도 개인 도감, 검색, 상세, 기존 세션을 사용할 수 있다.
- 로그인 상태가 세 가지 상태로 정확히 표시된다.
- 사용자가 로그인하면 성공을 확인하고 브라우저가 정확히 한 번 닫힌다.
- 숨김·보이기 실행 모두 사진 전체 첨부와 실제 전송을 확인한다.
- Quick Value 2장과 Deep Inspect 8장 첨부, 부분 실패, 취소, 타임아웃을 검증한다.
- 준비된 로그인 세션에서 사진 선택부터 Quick Value 카드까지 대부분 20초 안에 완료되는지 실제 기기에서 측정한다.
- Quick Value는 어떤 경우에도 45초를 넘겨 계속 기다리지 않는다.
- AI의 중간 스트리밍 결과나 이전 답변을 저장하지 않는다.
- 잘못된 가격 구조와 허용하지 않은 결과 값을 거부한다.
- 결과는 한 작업당 정확히 한 번만 저장된다.
- 로그에 사진, 프롬프트, 답변, 쿠키가 남지 않는다.
- 실제 기기에서 로그인 → 사진 2장 → 빠른 가치 → 저장 → 추가 촬영을 끝까지 검증한다.

## 20. 비용과 운영 현실

이 설계가 없애는 비용:

- DenimDex 상시 애플리케이션 서버
- 중앙 데이터베이스 서버
- 사용자 사진 저장 서버
- 개발자 소유 OpenAI API 사용료
- API Key 보안 운영

사용자 또는 제품에 남는 비용과 의존성:

- 사용자가 선택한 AI 서비스의 이용 조건 또는 유료 구독
- Apple Developer Program과 앱 배포 비용
- Archive 조사·저작권 확인·콘텐츠 제작 시간
- AI 제공자 웹 UI 변경에 따른 AIBI 어댑터 유지보수
- NAS 전기, 저장장치 백업, 도메인·TLS, 보안 업데이트
- App Store 정책 및 각 AI 제공자 이용약관 검토

따라서 DenimDex v2.0의 정확한 목표는 다음과 같다.

> 자체 상시 서버 없이 동작하고, AI 사용 비용은 사용자가 선택한 AI 서비스 관계 안에서 처리하며, 데이터와 분석 기록은 기본적으로 사용자의 기기에 남기는 제품.

## 21. 최종 사용자 경험

```text
모르는 빈티지 데님을 발견한다.
  ↓
DenimDex로 사진 두 장을 찍는다.
  ↓
사용자가 로그인해 둔 AI가 한 번에 분석한다.
  ↓
약 20초를 목표로 제품 후보, 상태, 참고 가격 범위를 본다.
  ↓
결과를 내 도감에 저장한다.
  ↓
원할 때만 사진을 한 장 더 찍거나 근거 조사를 시작한다.
```

기술은 뒤로 숨고, 사용자는 `두 장 찍기 → 가격 범위 보기 → 저장하기`를 먼저 경험해야 한다.
